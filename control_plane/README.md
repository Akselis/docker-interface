# Control Plane

## Alembic migrations

Migrations are configured under `control_plane/alembic` and discover SQLAlchemy models from `control_plane/db/models`.

### Prerequisites

- `DB_URL` environment variable set to your target database URL.
  - Runtime accepts either async URLs directly (e.g. `postgresql+asyncpg://...`) or common sync URLs (e.g. `postgresql://...`, `mysql://...`, `sqlite:///...`) and converts them to supported async drivers.
  - Alembic automatically converts async URLs to sync driver URLs for migration execution.
- Install dependencies from the project root `requirements.txt`.

### Database backend support

Runtime currently supports these async backends:

- PostgreSQL (`postgresql+asyncpg`)
- MySQL (`mysql+aiomysql`)
- SQLite (`sqlite+aiosqlite`)

You can provide either:

- full `DB_URL` directly, or
- compose variables (`DB_SCHEME`, `DB_ASYNC_DRIVER`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME`) and let compose build the URL.

### Docker Compose dynamic DB URL

`control_plane/docker-compose.yml` now builds `DB_URL` like this when not provided explicitly:

```/dev/null/compose-env.txt#L1-1
${DB_SCHEME:-postgresql}+${DB_ASYNC_DRIVER:-asyncpg}://${DB_USER:-control_plane}:${DB_PASSWORD:-control_plane}@${DB_HOST:-db}:${DB_PORT:-5432}/${DB_NAME:-control_plane}
```

Examples:

- PostgreSQL (default):
```/dev/null/env-postgres.txt#L1-4
DB_SCHEME=postgresql
DB_ASYNC_DRIVER=asyncpg
DB_HOST=db
DB_PORT=5432
```

- MySQL:
```/dev/null/env-mysql.txt#L1-4
DB_SCHEME=mysql
DB_ASYNC_DRIVER=aiomysql
DB_HOST=mysql
DB_PORT=3306
```

- SQLite (use explicit `DB_URL` to avoid host/port/user fields):
```/dev/null/env-sqlite.txt#L1-1
DB_URL=sqlite+aiosqlite:////app/control_plane/data/control_plane.db
```

When using an external database, set `DB_HOST` accordingly and run compose without the optional local db profile.

### Create revisions before DB is up

If the database is not available yet, create an empty revision and fill `upgrade()` / `downgrade()` manually:

```/dev/null/commands.sh#L1-1
sh scripts/makemigrations.sh "describe_change"
```

### Create a migration from model changes (requires DB connectivity)

Run from `control_plane` directory when DB is reachable:

```/dev/null/commands.sh#L1-1
alembic revision --autogenerate -m "describe_change"
```

### Apply migrations

```/dev/null/commands.sh#L1-1
alembic upgrade head
```

### Roll back one revision

```/dev/null/commands.sh#L1-1
alembic downgrade -1
```

### Notes

- Runtime compose migration step now checks drift, auto-generates a revision when needed, then runs `upgrade head`.
- Auto-generated revision files are written under `alembic/versions` through the bind mount in `docker-compose.yml`.
- If no models exist yet in `db/models`, autogenerated migrations will be empty.
- Add model modules under `db/models` and ensure they inherit from `db.models.base.Base`.
